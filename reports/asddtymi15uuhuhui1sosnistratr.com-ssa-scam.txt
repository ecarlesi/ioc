## Description

A randomized-string domain, registered one day before discovery via
Ultahost, Inc. (Cloudflare nameservers), serves an open directory
(LiteSpeed autoindex) hosting a **fake US Social Security
Administration (SSA) "secure document" lead-generation kit**. Unlike
classic credential-phishing kits, this one is a funnel toward
**abuse of legitimate remote-access/RMM software**: after a CAPTCHA
gate and a Windows-only filter, victims are served a genuine,
digitally-identifiable **RemotePC Host installer (IDrive Inc.)** as
the "secure document" download. A separate `Links.txt` file contains
755 pre-generated session-join URLs for a **self-hosted ConnectWise
ScreenConnect relay**, almost certainly used during a companion
phone-based "tech support" social-engineering call.

The domain hosts **both the raw kit archive AND a live, currently
running deployment** of the same kit (directory last-modified AFTER
the archive's own upload timestamp) — confirming this is an actively
staged, not abandoned, delivery host. The live deployment's payload
(a different RemotePC Host build/hash than the archived copy) shows
the operator periodically refreshes the abused installer with a
current copy of the legitimate IDrive product.

Every visit is logged (IP, geolocation, OS, browser, timestamp) and
pushed live to a Telegram bot; the bot's own webhook configuration
(discovered via the Telegram API, not present in any kit file) points
to a second, previously-unknown SSA-impersonation domain,
`ssa-gov.es`, revealing a more complete backend application behind
the flat PHP front-door kit analysed here.

## Impersonated brand

```
US Social Security Administration (SSA) -> ssa.gov (real government agency)
```

The kit hotlinks the real `ssa.gov/favicon.ico` and reuses (in
`assets/js/`) code that closely mirrors `ssa.gov`'s own internal
front-end framework (`SSA.namespace`, `SSA.fn.uef.*`, Google Analytics
property `UA-25977386-2`, GTM container `GTM-5GQXH7Q`) — most likely
lifted wholesale from a scrape/mirror of the real site.

## Kill chain

1. `index.php` — SSA-branded "Complete reCAPTCHA" page (real Google
   reCAPTCHA Enterprise widget). Non-Windows visitors are redirected
   to `devices.html` before the CAPTCHA resolves.
2. `devices.html` — "Access Restricted... use a Windows-based system"
   modal for non-Windows visitors, with right-click/F12/devtools
   blocking.
3. `download.php` — "Your SSA Secure Document is Ready" page with a
   fake progress bar, auto-redirecting to `download_file.php`.
4. `download_file.php` — streams a random file from `download/`
   (currently the RemotePC Host installer) as an attachment.
5. `notify.php`/`main.php` — geolocates every visitor (`ipinfo.io`),
   logs to a local file, and pushes to a Discord webhook (unconfigured
   in this snapshot) and a live Telegram bot simultaneously.
6. `Links.txt` — a parallel, independent vector: 755 pre-generated
   ConnectWise ScreenConnect session-join URLs for live remote-support
   sessions with victims, presumably driven during a phone call.

## TTPs

- Fake-government-document lead-generation funnel with a hard
  Windows-only gate (mobile/other-OS visitors are diverted before
  ever reaching the payload).
- Abuse of a **legitimately signed, commercial RMM/remote-access
  product** (RemotePC Host by IDrive Inc.) as the "malware" — far
  harder for signature/hash-based AV to flag than custom malware.
- Independent **self-hosted ConnectWise ScreenConnect** relay for
  live remote-support sessions, with a large pre-generated batch of
  session-join links ready ahead of a calling campaign.
- Dual-channel live visit telemetry (Discord webhook + Telegram bot)
  with operator handle rotation over time (`Quartz` -> `error_new25`)
  suggesting either a handle change by the same actor or a
  kit-sharing/reselling model.
- Payload rotation: the operator periodically re-fetches a fresh copy
  of the legitimate installer rather than reusing one static binary,
  likely to avoid accumulating a stable hash/version signature.
- Reuse of the real ssa.gov front-end JS/analytics framework as
  camouflage/legitimacy signal.
- Live infrastructure pivot via the Telegram Bot API: the bot's own
  webhook configuration exposed a second, previously unknown
  SSA-impersonation domain not referenced anywhere in the kit's files.
